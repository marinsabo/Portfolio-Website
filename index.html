The application

DartZ runs entirely on z/OS. CICS handles the transactions and the terminal screens, COBOL programs hold the business logic, and Db2 stores everything: players, matches, legs, tournaments and leagues. Compiling and batch work run through JCL.

  • z/OS
  • COBOL
  • CICS
  • Db2
  • JCL

My role

  • Designed the entire Db2 data model and built it, which every program in the application depended on.
  • Created the test data the developers used to test their programs.
  • Kept the database consistent as the team’s Db2 and z/OS administrator, maintaining the environment the whole team worked in.
  • Worked on the DevOps modernisation once the application was finished.

Modernisation: from datasets to Git

After DartZ was finished, we changed how it’s built and delivered, following IBM Dependency Based Build (DBB). The source of truth moved off the mainframe into Git, and a pipeline now delivers every committed change to z/OS automatically.

Before Source lived in mainframe datasets, and builds were run on the host with JCL.
After Source lives in Git. A commit triggers the pipeline, which builds and delivers the change to the mainframe.
  1. VS CodeCOBOL, JCL and copybooks edited locally
  2. GitSingle source of truth, where every change is a commit
  3. PipelineStarts automatically on each push
  4. IBM DBBBuilds the programs affected by the change
  5. Zowe → z/OSChanges land on the mainframe

Why mainframe

I prefer mastery and real craft over chasing the next shiny framework that will change in two weeks.

That’s why I want to build my career on enterprise systems.
